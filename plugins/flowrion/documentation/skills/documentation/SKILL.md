# Documentation

Write for the reader who has to act on it.

1. Start with what the reader can do or must know; background comes after.
2. Use the product's own terms consistently, and define a term the first time it appears.
3. Prefer steps, tables and examples to long paragraphs; label example data as example.
4. Keep commands copyable and correct; run them if you can.
5. Say what is not covered and where to find it.
6. Update the docs that the change makes wrong, not only the new page.
